Arithmetic a model can actually use.

Storing arithmetic in an embedding is easy — combine two number-waves and the answer's wave falls out, exactly, with zero parameters. The hard part, and the part nobody had closed, is getting a learned model to use it and generalize. This does: a Homomorphic Operator Layer turns the exact operation into an architectural primitive, so a tiny network does arithmetic on numbers far outside its training range — where a standard model scores near zero.

by Kunal Sinha
Method · the number code

A number is a wave; operations are products of waves.

Each number is stored as a bank of complex phasors — a spectral (Fourier) code. Two homomorphisms fall straight out of the phase, so a fixed elementwise product computes the operation exactly, for any inputs, with no trainable parameters.

additive code — + and −

Adding numbers = adding phases.

With a(n)=e^{iω_k n}, shifting the number rotates every phasor, so a(x+y)=a(x)·a(y). Subtraction is the complex conjugate. A matched filter reads the exact integer back.

a(x+y) = a(x) ⊙ a(y) (⊙ = elementwise complex product)
log code — × and ÷

Multiplying numbers = adding log-phases.

With m(n)=e^{iω_k ln n} and ln(xy)=ln x+ln y, multiplication becomes the same elementwise product; division is the conjugate.

m(x·y) = m(x) ⊙ m(y)

The result · 3 seeds

It generalizes to magnitudes it never saw.

Task: answer templated natural-language queries like "<a> plus <b>" (each operation has several phrasings). Train only on numbers below 80; test on pairs whose larger operand is ≥ 80 — magnitudes never seen. The operator layer learns only the easy language→operation mapping; the exact bind handles the numbers, so it extrapolates. A standard model given the same features does not.

The operator layer reaches 99.7% on numbers outside its training range; the MLP on the same spectral features stays near 0. Handing a network the right structured features is not enough — the generalization comes from making the operation part of the architecture.

Why it works

Learn the language, not the arithmetic.

The layer splits the problem along its natural seam: a model should learn what a query means, but it should never have to learn arithmetic — that is fixed and known. Making the operation an exact primitive is what turns "memorize a range" into "compute for any magnitude."

step 01

Encode

Numbers become spectral waves; the query words become ordinary learned token embeddings.

step 02

Gate

A tiny learned gate maps the phrasing (plus / add / sum → +) to an operation. This is the only thing trained, and it generalizes across phrasings.

step 03

Bind & decode

The selected exact bind combines the number-waves; a fixed decoder reads the integer. No parameters, valid for any magnitude.

The number code is a generic Fourier phasor bank — deterministic and invertible — appended alongside the word/byte dimensions, exactly the "keep the existing dims for language, add math in new ones" split.
